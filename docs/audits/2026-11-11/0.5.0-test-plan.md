# 0.5.0 test plan

Written on 11 November 2026 for the operator's decision of the same day to cut 0.5.0 as the first tagged release, with its Linux packages published on GitHub.
Rewritten on 19 November 2026 for the operator's decision that manual testing be "non-existent, or absolutely minimal": every step a browser can see is now a journey, and this plan keeps only what needs a person at the desktop.
The steps of the plan as it stood on 18 November, and of the [0.1.0 plan](../2026-09-24/0.1.0-test-plan.md) it carried, are in this file's history; the table at the end says where each one went.
A failed step blocks the tag ([RELEASING](../../RELEASING.md)).
Results go in `0.5.0-test-results.md` beside the candidate: one row per step, what was observed, pass or fail, and the evidence.

## A. What the author runs on the candidate

These are not the operator's steps; the candidate's results sheet records them.

- The full local gate, PR and master CI, and the release build of the commit to be tagged.
- The packages' provenance, the tarball's `--version` and `--engine`, and a clean install of the rpm in a fresh Fedora 44 container and of the deb in a fresh Ubuntu 24.04 container.
- The browser journeys on the mock and both real clouds, `make uijourneys CLOUDS=<clouds.yaml>`, and again on the mock alone, `make uijourneys`, which adds the journeys that restart the application.
- The service journeys on both real clouds, `make journeys CLOUDS=<clouds.yaml>`.

What the journeys cover, and how each checks its outcome, is the table in [docs/journeys.md](../../journeys.md).

## B. Before starting

- Install the candidate's rpm on the Fedora host: `sudo dnf install ./<name>.rpm`.
- Make the local files the steps use: `scripts/test-fixtures.sh ~/aeronautes-fixtures` from a checkout of the candidate's commit.
- Use a test account and test containers, never data that matters, and start the application from a terminal so its output is kept.

## C. Steps for a person

1. **The installed application.**
   Run `aeronautes --engine` and `aeronautes --version`, then start it from the desktop's application menu.
   Expected: the engine reports rclone v1.74.3 verified, the version is `dev` with the candidate's revision, and the window opens and connects to a bookmark.
2. **Closing the window during a save.**
   Open an object's metadata editor, change a value, press save and close the window at once with its close button or the desktop's quit key; start it again.
   Expected: it exits within a few seconds and starts again with no lock complaint.
   That "Recent changes" and the store agree after such a quit is journeyed at three timings; only the window's own close button and quit key need a person.
3. **A native question, refused by keyboard and by closing.**
   Upload a file from `~/aeronautes-fixtures/replace/` onto a name that exists, press "Replace 1 existing object…" and "Start upload", and answer the native question with Escape; then again and close the question's window.
   Expected: each time nothing is written and the page says so.
   The journeys answer every native question yes and no and check its words; every question is drawn by the same native dialog, so Escape and closing are checked on this one.
4. **The keyring.**
   Create a bookmark with a saved key and see its item in the desktop's keyring ("Passwords and Keys"); delete the bookmark.
   Expected: the item is gone and the credential status reports no pending cleanup.
5. **The window noticing a change made elsewhere.**
   Create a container with another tool (`swift post <name>`), use another application for more than thirty seconds, and click back into Aeronautes.
   Expected: the container is listed without pressing anything.
   The thirty-second rule and the listing on returning are journeyed with a moved clock; only the desktop giving the window its focus back needs a person.
6. **Drawing without the graphics card.**
   In Settings, untick "Use the graphics card", quit and start again.
   Expected: the window works, drawn in software; tick it again.
7. **The log switches at launch.**
   Start the application from a terminal with `AERONAUTES_LOG_LEVEL=warn AERONAUTES_LOG_FILE=/tmp/aeronautes-test.log aeronautes`, open Settings, then download a folder and quit.
   Expected: Diagnostics says "warn in force, set by AERONAUTES_LOG_LEVEL at launch" and that the file is being written, named by AERONAUTES_LOG_FILE; the file holds the session.
   Keeping a log file from Settings, and that no key reaches any log, export or page, are journeyed.
8. **The clipboard.**
   Press an object's "Copy name", the ETag's copy button, a job's "Copy details" and the log file path's copy button, pasting each into a text editor.
   Expected: each pastes what it names; the journeys press them, but their build has no clipboard to read back.
9. **How it looks at your own size.**
   With the window at the size you use, look over the main screen, the dialogs and the jobs drawer, with a long container and object name.
   Expected: nothing is cut off, overlaps or lies outside its dialog, and the hover bubbles read whole.
10. **Keystone v3 discovery and IDs.**
    Only where a Keystone v3 endpoint is available: create a bookmark with that auth type, then try the Identity URL without `/v3`, and with user and project IDs in place of their names.
    Expected: both connect and browse.
    Making a Keystone v3 bookmark in the editor, connecting and refusing an address with no Keystone v3 are journeyed on the mock; without an endpoint, record not run; it does not block the tag.

## Results

The plan passes when every step in C passes, or is recorded as not run where it allows, and the author's checks in A are green.
