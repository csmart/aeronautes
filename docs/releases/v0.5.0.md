Aeronautes 0.5.0 is the first tagged release: a desktop workbench for OpenStack Swift and SwiftStack that browses, inspects, edits, transfers and deletes with the store's own semantics made explicit.

**Read before using it against data that matters.**
These builds are unsigned, and only Linux is supported, on x86_64 and aarch64: Fedora current stable is the reference platform, and the deb targets Ubuntu current LTS, where installation has not yet had its own acceptance run.
The valuable-data release hold remains: the evidence its acceptance gates require is not complete, so use dedicated test accounts and containers first, as the [README](https://github.com/csmart/aeronautes#before-trusting-a-release-against-production) describes.

## What it does

- Browse containers and very large containers page by page, with Logical, All and Backstage views, Find, and prefix counts.
- Inspect accounts, containers and objects: headers, metadata, ACLs, storage policies, large objects (DLO and SLO) and their segments.
- Edit object, container and account metadata, container ACLs (with a native confirmation before anything is made public), quotas, TempURL keys, CORS and legacy versioning locations; create containers with a storage policy.
- Upload files or a whole folder, download a prefix, and copy between bookmarks, each checked completely before anything is written; replacing an existing object needs a native confirmation.
- Delete an object, a selection, a marker, a manifest, a prefix or a container's contents, with a preview of what will go. A single object, marker or manifest is confirmed with a button; a selection asks you to type its count, a prefix or container deletion the container's name, and a large object's segments are deleted only from Backstage with the object's name typed. Before each delete the name is checked again against what was listed, or read afresh where the listing cannot settle it.
- Run up to four jobs at once (two by default), pause and resume them, and read each job's per-object records and recorded settings.
- Authenticate with TempAuth v1 or Keystone v3; credentials stay in the system keyring.
- Back up and restore the configuration, without credentials.

## In this build beyond 0.5.0's plan

Uploads and downloads take the performance profile and per-job overrides the copy dialog already offered, and each job records where each value came from.

## Files

For each architecture: an rpm, a deb and a tarball, each carrying the pinned rclone v1.74.3 it verifies before use, and a `.provenance.json` with every file's SHA256.
macOS and Windows builds are development builds without acceptance and are not attached.

## Known issues

- No whole-application memory ceiling: a download's plan holds its whole inventory, measured on the development host at about 352 MiB of peak resident memory at the default limit of 250,000 objects, and many large downloads queued together can hold several GiB.
- Mirror shows a comparison preview only and refuses to start.
